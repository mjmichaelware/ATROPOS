**CLI / TUI UX best practices (standards + patterns)**  
- Human-first / discoverable design (cli-guidelines): progressive disclosure, comprehensive yet concise help, examples, next-action suggestions, consistent naming.  
- Hierarchical menus: drill-down (category → subcategory when ≥8 items → leaf commands → full doc leaf) reduces visual density; alphabetical top-level + scope preview on hover/focus.  
- Navigation lingua franca: ↑/↓, ←/→ or Enter to drill, Esc back/close, ? for context help, Tab for cycle where appropriate. Footer or top chrome always shows current key map.  
- Autocomplete + synonym support: prefix + alias matching so “status” surfaces usage/tokens/context etc.  
- Multi-surface consistency: same trie + same key semantics across native terminal, web (WebSocket direct-to-engine), Android (in-process).  
- Mobile/hardware abstraction: no hard-coded absolute paths; dynamic tool discovery via PATH; user-definable keybind strings (e.g. `#ABC`) that expand to any internal action, with confirmation and bounds.  
- CS fundamentals surfaced: modularity of the 4-tier trie (domain → subcategory → action → documentation leaf), separation of command registry from rendering, capability attenuation (model vs write), reproducibility (CAS hashing), zero-trust territory checks.  


These findings confirm the 4-tier trie, synonym resolution engine, auto-popup modals, and omni-surface requirements are on solid ground; they also highlight gaps in the prior document around complete competitive inventories, explicit complexity/performance notes for large command sets, security of custom keybinds, and testability of the navigation state machine.

- Trie performance & memory: with 100+ commands + variants, prefix search and rendering must stay sub-frame on mobile/Termux (suggest radix/trie + lazy leaf loading).  
- Accessibility & density trade-off: color schemes must remain readable under high-contrast / reduced-motion; animation speed setting already present—extend to reduced-motion.  
- Extensibility: plugin/MCP commands should appear in the same categorized trie without breaking alphabetical or depth rules.

- Failure modes: what happens on partial render (narrow terminal, web resize, APK orientation change)? Need responsive breakpoints and graceful degradation.  
- Versioning of the command surface itself so future ATROPOS releases can deprecate without breaking muscle memory.
