## 1. Purpose and Absolute Completion Definition

This document is the single ordered blueprint required to move ATROPOS from its current state (~60%) to absolute completion (100%).

**Absolute completion is reached only when all of the following are true simultaneously:**

1. Every Source Docs 1–2 atom (94 atoms) is mapped to exact source coordinates, implementation symbols, behavioral tests, immutable evidence, and a passing acceptance gate.
2. Every applicable Source Doc 3 requirement (74 items) is implemented with the same rigor.
3. All Hierarchy Research patterns are absorbed into the existing phases without parallel architecture.
4. Every critical stub is eliminated (`ConstraintSolverEvaluator`, `TokenIsolationVault`, `TreeSitterGrammarBridge`, and any remaining constant-true or empty implementations).
5. Extreme per-file atomic decoupling is enforced across the entire tree (no remaining multi-thousand-line mixed-concern files).
6. The installed runtime proves:
   - Inside-out self-build (Phase 11)
   - Lovable/Base44-class full-stack natural-language app generation with live preview, testing, and deployment (Phase 19)
   - Long-horizon autonomous continuation across interruptions with restart continuity and evidence-backed evaluation (Phase 20)
7. Final Git state is clean. No untracked implementation debt remains. No fake-success paths remain.

This document does not invent replacement phases. It expands the existing 21-phase map (Phase 0–20) with the exact gap-closure order, missing atomic components, and acceptance predicates required for 100%.

## 2. Non-Duplication Law (Hard Rule)

Before any new class or file is added:

1. Resolve the exact source requirement and acceptance predicate.
2. Query the current symbol graph and direct callers.
3. Select the existing semantic owner.
4. Extend or compose that owner.
5. Add a new atomic component only when no existing owner can satisfy the responsibility without mixing concerns.
6. Never create a second DAG, territory system, verifier, policy engine, memory root, queue, journal, provider registry, or artifact pipeline.
7. If a Source Doc 3 name overlaps an existing subsystem, implement it as a narrow facade/contract over that subsystem.
8. Update the source-to-code ledger, tests, evidence, and symbol census in the same batch.

## 4. Critical Current Debt That Must Be Closed Early

These items currently prevent truthful claims of completion. They are ordered by blocking power:

1. **ConstraintSolverEvaluator** — three-line constant-true stub. Must become a real deterministic constraint evaluator or be removed and replaced by explicit invariant checks inside DeterministicVerifier.
2. **TokenIsolationVault** — three-line constant-true stub. Must become real local secret isolation.
3. **TreeSitterGrammarBridge** — effectively empty. Must become real deterministic parsing or an equally deterministic alternative that feeds AstSymbolGraph.
4. **ScaffoldAdapters.kt (~1,390 lines)** — must be split into atomic transport, request, response-normalization, and error-mapping files.
5. **DirectorOrchestrator / WorkerCodeSynthesizer** — paths that allow models to invent file plans or write provider output directly. Must be retired or rewritten to respect territory, source authority, and independent verification.
6. **Large mixed-concern files** (AgentCommand.kt, AgentRunService.kt, AgentPatchStore.kt, DloiService.kt, and others) — must be brought under extreme atomic decoupling.

## 5. Extreme Per-File Atomic Decoupling Campaign (Cross-Cutting)

This is elevated to a first-class, continuous requirement rather than a side note.

**Rule:** One file = one atomic responsibility. No file may mix presentation, decision logic, transport, normalization, verification, and persistence.

**Enforcement mechanism:**
- `ArchitectureComplianceChecker` must be expanded into a fast-gate and full-verification rule.
- Configurable line thresholds + concern-category detection (routing + rendering, transport + normalization, verification + execution, etc.).
- Violations begin as advisory, then become blocking.
- Every Phase 0–20 batch that touches code must leave the tree in a better or equal atomicity state.

**Explicit split targets (must be completed before Phase 19 is declared done):**
- ScaffoldAdapters → separate transport / request / normalization / error-mapping files per provider family.
- Remaining large agent and DLOI files → extract single-responsibility components.
- Any new file created after this blueprint must itself obey the one-responsibility rule.

- **Fallback proof:** external planning plugins and cloud providers can disappear without destroying core planning or execution.
- **Learning proof:** evidence changes bounded routing, retry, batch-size, or repair weights while invariants remain immutable.
