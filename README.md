# ATROPOS

> **The Sovereign Engine for Building Software That Builds Itself**

**Local-first. Deterministic. Self-improving. Policy-governed.**

ATROPOS is a production-grade, Android/Termux-native CLI engine designed to be the reliable core of a personal software development organization. It treats source code as authority, verification as non-negotiable, and persistent memory as a first-class citizen.

It is built for developers who want to own their tools, their process, and their long-term velocity — without surrendering control to cloud platforms or opaque agents.

---

## The Vision

Most AI coding tools optimize for speed and convenience.  
ATROPOS optimizes for **correctness, sovereignty, auditability, and compounding improvement over years**.

It is the engine you use to build other tools — and the engine that gets better every time you do.

## Core Philosophy

| Principle              | What It Means                                                                 | Why It Matters |
|------------------------|-------------------------------------------------------------------------------|----------------|
| **Symbolic Authority** | Exact DLOI addressing + AST symbol graphs instead of blind retrieval         | No hallucinated context |
| **Deterministic Verification** | `E(Δ) = 0` gates before any commit or state change                           | Trustworthy self-modification |
| **Territory & Governance** | Hierarchical swarm with explicit boundaries and Director oversight           | Safe autonomy at scale |
| **Local-First**        | Full operation on Termux/Android with zero cloud dependency by default       | Privacy, offline work, ownership |
| **Self-Improvement**   | Real feedback loops from compilation, verification, and usage                | The engine gets meaningfully better as you build |
| **Policy-Bound**       | Free-first routing with explicit paid emergency unlocks                      | Cost control + intentionality |

## How It Connects to the Rest of the Stack

ATROPOS is designed as the **execution and self-improvement layer** of a larger sovereign development system.

- **SpecGraph Foundry** acts as the high-fidelity planning and verification substrate. It turns complex requirements into research-enriched, independently verifiable blueprints and handoff artifacts that ATROPOS can consume cleanly.
- **MusicMakerLM** is one of the first major domain applications being built with this stack — a symbolic, emotionally-aware music system that demonstrates the depth ATROPOS can support when used as an app factory.

The three projects together form a closed, sovereign loop:
**SpecGraph plans → ATROPOS executes & improves → Domain apps (like MusicMakerLM) ship with real provenance and governance.**

This is not three separate tools. It is one coherent philosophy expressed across planning, execution, and creative domains.
